# Проект: веб-игра — прогулка по деревне полуросликов

## Что это

Браузерная 3D-игра: небольшой уютный мир, населённый полуросликами.
Исследование, бытовые занятия, никакой боёвки.

**Цель проекта — витрина навыков в 3D-вебе, а не коммерческий продукт.**
Отсюда приоритет: качество картинки и плавность важнее объёма контента.
Лучше маленький мир, который выглядит дорого, чем большой и пустой.

## Ограничение по названиям

Проект вдохновлён Широм Толкина, но имена из его вселенной защищены
товарными знаками. В коде, в UI, в текстах игры и в публичных именах
репозитория **не использовать**: Shire, Hobbit, Baggins, Middle-earth,
Brandywine и другие имена собственные из легендариума.

Использовать нейтральные: `halfling`, `village`, `valley`, `river`.
Визуальный язык (норы в холмах, круглые двери, сельский уют) — можно.

Правило распространяется на всё, что попадает в репозиторий, включая
имена файлов в `assets/`. Исключение одно — корневая папка на диске
(`D:\hobbits\`): она не публикуется, переименовывать не нужно.

Репозиторий: https://github.com/nasraddinzade/halflings

## Стек

- Vite + TypeScript (строгий режим)
- three.js, ванильный — **без react-three-fiber**
- three-mesh-bvh для коллизий по террейну; полноценный физдвижок не нужен
- Без бэкенда, всё раздаётся статикой

## halfling_base.glb — что уже сделано

Источник: KayKit Adventurers 2.0 FREE, персонаж Rogue. Лицензия CC0.

- Скелет `Rig_Medium`, 23 кости
- 6 отдельных мешей: `Rogue_Head` (2606 тр.), `Rogue_Body` (1436),
  `Rogue_ArmLeft` / `Rogue_ArmRight` (по 788),
  `Rogue_LegLeft` / `Rogue_LegRight` (по 930). Итого ~7500 тр.
- Плащ, оружие, камера и источник света удалены
- Экспортирован **в родном масштабе Blender**, высота 2.1804 юнита
- Текстура — градиентный атлас 1024×1024, общий на всего персонажа

## Ключевые константы

```ts
export const CHARACTER_SCALE = 0.50451; // приводит модель к росту 1.1 м
export const HALFLING_HEIGHT = 1.1;     // метрика мира, метры
```

Весь мир строится от роста 1.1 м: двери ~1.3 м, потолки нор ~1.6 м,
трава ~0.3 м, ступени ~0.15 м.

**Не менять масштаб внутри GLB-файлов.** Только
`model.scale.setScalar(CHARACTER_SCALE)` в коде. Причина: клипы анимаций
лежат в оригинальном масштабе, рассинхрон даёт проскальзывание ног
и проваливание персонажа сквозь землю.

## Анимации

В `KayKit_Character_Animations_1.1/Animations/` клипы разложены наборами
по категориям и разделены по типу рига.

Использовать **только файлы для `Rig_Medium`**. Нужные категории:
- **General** — айдлы, взаимодействия
- **Movement** — ходьба, бег, прыжки, приседания
- **Simulation** — эмоции: махать, сидеть, лежать
- **набор с инструментами из версии 1.1** — Chop, Dig, Fishing_*, Hammer,
  Saw, Pickaxe, Work_*, Holding_*. Это занятия для NPC деревни

Не использовать: Melee, Ranged, Special.

В паке Adventurers есть своя папка `Animations` с базовым набором —
она беднее, приоритет у отдельного пака анимаций.

Клипы проигрываются на скелете персонажа напрямую, ретаргет не нужен —
имена костей совпадают:

```ts
const char = await loader.loadAsync('/assets/characters/halfling_base.glb');
const anims = await loader.loadAsync('/assets/animations/movement.glb');
const mixer = new THREE.AnimationMixer(char.scene);
const clip = THREE.AnimationClip.findByName(anims.animations, 'Walking_A');
mixer.clipAction(clip).play();
```

## Архитектурные решения — приняты, не пересматривать без вопроса

1. **Шесть мешей персонажа склеиваются в один `SkinnedMesh` при загрузке.**
   Иначе 6 draw calls на каждого NPC. Склейка — после выбора частей
   по конфигу.

2. **Жители собираются из конфига, а не хранятся отдельными файлами.**
   Все персонажи пака сидят на одном `Rig_Medium`, поэтому части разных
   персонажей взаимозаменяемы:

   ```ts
   interface VillagerConfig {
     id: string;
     head: string;   // 'Rogue_Head' | 'Mage_Head' | ...
     body: string;
     arms: string;
     legs: string;
     palette: { head: number; body: number; legs: number };
     role: 'gardener' | 'miller' | 'fisher' | 'idler';
   }
   ```

   Конфиг детерминированно выводится из seed (имени жителя), чтобы один
   и тот же NPC выглядел одинаково между сессиями.

3. **Перекраска — сдвиг UV по атласу**, а не новые материалы и не новые
   текстуры. Атлас KayKit — регулярная сетка **8×4 ячейки по 128×256 px**,
   шаг 0.125 по U и 0.25 по V (замеры в `docs/ASSETS.md`, раздел 6).

   Сдвиг **запекается в `TEXCOORD_0` во время склейки шести частей**
   (см. п.1), а не выставляется через `map.offset` у материала. Причина:
   после склейки на весь меш один материал, и одним `map.offset` нельзя
   покрасить голову иначе, чем ноги, — а `VillagerConfig.palette` требует
   именно этого. К вершинам каждой части прибавляется свой `(du, dv)`.
   Один материал, одна текстура, один draw call.

   Текстура — **своя, сгенерированная по той же сетке 8×4** из
   `config/palette.ts`: 32 ячейки, в каждой 2–3 плоские ступени.
   Паковые атласы не годятся: в их ячейках запечён плавный градиент,
   поверх которого toon-ступени дадут грязь, плюс у пяти паковых атласов
   на одной позиции сетки разные цвета. UV при этом не трогаются —
   развёртка пака остаётся валидной, Blender не нужен.

4. **Границы мира диегетические** — долина, замкнутая холмами и рекой.
   Никаких невидимых стен, никакого сферического мира.

5. **Toon-шейдер + обводка inverted hull.** 2–3 ступени освещения,
   не градиент. Обводка не чёрная, а затемнённый цвет самого объекта.

6. **Единая палитра на весь проект.** Ни один ассет не приносит свои цвета.

## Чего не делать

- Не трогать пропорции костей и рест-позу — сломает совместимость с клипами
- Не добавлять боёвку, оружие, врагов, износ снаряжения
- Не строить большой открытый мир: ориентир — долина, проходимая пешком
  минут за пять
- Не тащить физический движок ради коллизий с землёй
- Не генерировать персонажей ИИ-инструментами. Персонажи только из CC0-паков
  (для пропсов и окружения ИИ-генерация допустима)
- Не использовать localStorage / sessionStorage без явной просьбы

## Стиль кода

- TypeScript строгий, без `any`
- Модули по зонам ответственности: `core/`, `world/`, `character/`,
  `render/`, `config/`. Не давать одному файлу разрастаться
- Игровой цикл один, в `core/`. Не плодить `requestAnimationFrame` по модулям
- Все магические числа — в `config/constants.ts`
- Комментарии, код и идентификаторы на английском. Тексты игры и имена
  жителей остаются русскими — это содержание, а не код
