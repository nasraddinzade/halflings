# Каталог ассетов

Составлено разбором самих файлов, а не по именам. Временный скрипт-инспектор
парсил контейнер GLB вручную (заголовок → JSON-чанк → BIN-чанк) и считал:
треугольники по `accessor.count / 3` у индексного аксессора каждого примитива,
длительность клипа как максимум по `accessor.max[0]` входных сэмплеров
анимации (это ровно то число, которое three.js положит в `AnimationClip.duration`),
кости — по `skins[].joints` с разыменованием в имена узлов, UV — чтением
`TEXCOORD_0` из буфера, размеры PNG — из чанка IHDR. Скрипт лежал в
scratchpad и в проект не попал.

## 2. assets/characters/halfling_base.glb — сверка

Разбор подтверждает всё, что записано в CLAUDE.md:

- 6 мешей, **7478 тр.** суммарно: `Rogue_Head` 2606, `Rogue_Body` 1436,
  `Rogue_LegLeft`/`Rogue_LegRight` по 930, `Rogue_ArmLeft`/`Rogue_ArmRight` по 788
- плащ `Rogue_Cape` удалён, лишних узлов (камера, свет) нет
- скелет `Rig_Medium`, 23 кости, **рест-поза побитово совпадает с Rogue.glb**
- высота 2.1804, `2.1804 × 0.50451 = 1.1000` — константа верна
- одна встроенная текстура 1024×1024, **sha1 совпадает с `rogue_texture.png`**
  из пака: файл не перекодировался
- один материал `rogue`: `doubleSided = true`, `alphaMode = OPAQUE`,
  `metallic = 0`, `roughness = 0.5`
- экспортёр — Blender glTF I/O v5.2.39 (у файлов пака v1.7.33)

`doubleSided = true` стоит учесть на шаге стилизации: обводка методом
inverted hull делается через `side: BackSide` на копии меша, а
двусторонний материал ей мешает — оболочку надо делать отдельным
материалом с явным `BackSide`, а не клоном исходного.

## 3. Скелет Rig_Medium

23 кости. Иерархия (проверена по `nodes[].children`):

```
Rig_Medium (узел-контейнер, не кость)
└─ root
   └─ hips
      ├─ upperleg.l → lowerleg.l → foot.l → toes.l
      ├─ upperleg.r → lowerleg.r → foot.r → toes.r
      └─ spine → chest
                 ├─ head
                 ├─ upperarm.l → lowerarm.l → wrist.l → hand.l → handslot.l
                 └─ upperarm.r → lowerarm.r → wrist.r → hand.r → handslot.r
```

Полный список имён: `root`, `hips`, `spine`, `chest`, `head`,
`upperleg.l/r`, `lowerleg.l/r`, `foot.l/r`, `toes.l/r`,
`upperarm.l/r`, `lowerarm.l/r`, `wrist.l/r`, `hand.l/r`, `handslot.l/r`.

`handslot.l` / `handslot.r` — пустые кости-крепления на конце кисти,
готовые точки привязки для инструментов (лейка, удочка, корзина).

### Совпадают ли кости — да

Проверено попарно между всеми шестью персонажами Adventurers,
`halfling_base.glb` и всеми восемью файлами анимаций `Rig_Medium`:

- **имена костей** — идентичны, 23 из 23, ни одного расхождения
- **иерархия** — идентична
- **локальная рест-поза** (translation / rotation / scale каждой кости) —
  идентична с точностью до 1e-5

Порядок костей в массиве `skins[].joints` между файлами различается, но это
неважно: `THREE.AnimationMixer` связывает треки с костями **по имени узла**,
а не по индексу. Ретаргет действительно не нужен.

Каналы клипов адресуют только эти 23 кости, узлов вне скелета в анимациях нет.
Свойства — `translation`, `rotation`, `scale`.

### Два исключения, о которых надо знать

**`Mannequin_Medium.glb`** (`Mannequin Character/characters/`) — в его скине
**21 кость**, нет `handslot.l` и `handslot.r`. На сами файлы анимаций это не
влияет: там скин полный, 23 кости. Просто не использовать этот меш как эталон.

**`Rig_Large` — те же имена костей, но другой скелет.** Имена, иерархия и
количество (23) совпадают с `Rig_Medium` полностью, а рест-поза отличается
у 22 костей из 23: `hips` смещён на 0.636, `head` на 0.757, `upperarm.*` на
0.672 — модель вдвое выше (3.98 против 2.18). Это ловушка: клип из
`Rig_Large_*` **проиграется на нашем скелете без единой ошибки** и молча
изуродует персонажа. Ориентироваться только на путь файла, не на имена костей.

`KayKit_Adventurers_2.0_FREE/.../Animations/gltf/Rig_Medium/` содержит

### Root motion

Кость `root` анимируется каналом `translation` во всех клипах, но фактическое
смещение нулевое везде, кроме четырёх уворотов:

| Клип | Смещение root |
|---|---|
| `Dodge_Forward` | 0.25 по Z |
| `Dodge_Backward` | 0.65 по Z |
| `Dodge_Left` / `Dodge_Right` | 0.50 по X |

То есть **ходьба и бег бегут на месте** — перемещение целиком на
контроллере. Это то, что нужно: скорость персонажа задаётся кодом, а
скорость проигрывания клипа подгоняется под неё через `action.timeScale`,
чтобы ноги не проскальзывали.

Прошли на всех пяти файлах:

`tools/compress-animations.mjs` прогоняет их через
`EXT_meshopt_compression` (gltf-transform). В рантайме нужен
`MeshoptDecoder`, он подключается к загрузчику в `core/Game.ts`.

| Файл | После обрезки | После сжатия | По сети (brotli) |
|---|---:|---:|---|
| `general.glb` | 420 КБ | 217 КБ | 38 КБ |
| `movement.glb` | 285 КБ | 167 КБ | 24 КБ |
| `movement_advanced.glb` | 314 КБ | 202 КБ | 28 КБ |
| `simulation.glb` | 448 КБ | 235 КБ | 49 КБ |
| `tools.glb` | 1039 КБ | 430 КБ | 95 КБ |
| **итого** | **2.45 МБ** | **1.22 МБ** | **234 КБ** |

**Персонажей сжимать нельзя.** Проверено на `Rogue.glb`: gltf-transform
вместе со сжатием квантует геометрию, а для скиннованных мешей запекает
деквантизацию в `inverseBindMatrices` и расщепляет один скин на семь —
по одному на меш. Жители склеиваются из частей разных файлов на общий
скелет (`character/mergeSkinned.ts`), и после такой обработки части
приехали бы с разным масштабом. Инструмент это учитывает и трогает
только `assets/animations/`.

Оба инструмента сверяют результат с исходником по именам клипов,
длительностям, числу каналов и набору костей и отказываются записывать
файл, если что-то разошлось. Повторный запуск безопасен: уже сжатые
файлы пропускаются.

Перегенерировать по отдельности:

```bash
node tools/strip-anim-meshes.mjs
node tools/compress-animations.mjs
```

## 9. Находки и чем они кончились

Раздел писался по ходу инвентаризации, когда это были открытые вопросы.
Все три закрыты — оставлено ради истории решений.

**Перекраску сдвигом UV пришлось заменить ремапом по зонам.**
Сетка 8×4 регулярная, и сдвиг на 0.125 по U переносит острова части на
соседнюю колонку когерентно. Но UV-острова одной части размазаны по
четырём-восьми колонкам сразу (раздел 6), так что сдвиг двигал их все
разом: кожа уезжала на цвет ткани, ткань на цвет металла. Расцветки
не получалось — получалась лотерея.

Работает другое: ячейка пакового атласа трактуется как **зона
материала**, ведь так её и задал художник. На загрузке читается паковая
текстура, цвет каждой из 32 ячеек подтягивается к ближайшему тону
палитры, и UV каждой вершины переписывается на один тексель нового
атласа — колонка зона, строка вариант одежды. Разбиение авторское,
цвета свои, развёртка не тронута. Реализовано в `render/atlas.ts`,
запекается при склейке в `character/mergeSkinned.ts`.

Заодно снялся вопрос градиентов: свой атлас плоский, и toon-ступени
ложатся на него чисто. Понадобились два тона сверх палитры персонажей —
`ink` и `steel`: без них почти чёрный `#13191b` (это глаза) уезжал
в коричневый цвет сапог.

**Столкновение имени `T-Pose`** — решено отсевом на загрузке
(`IGNORED_CLIPS` в `config/assets.ts`).

**`doubleSided = true`** у паковых материалов помешать не успел:
`render/style.ts` выбрасывает материал из ассета целиком и ставит свой,
а обводка делается отдельным материалом с явным `BackSide`.

Что при этом всплыло уже на практике и в разделах выше не отражено:
у голов пака **23–45% вершин сидят на швах жёстких нормалей**, углы
между нормалями в одной точке доходят до 148°. Раздувание оболочки по
таким нормалям рвёт её, и в щели видны тёмные задние грани — грязными
пятнами вокруг глаз и рта. Лечится усреднением нормалей по совпадающим
позициям (`smoothNormal` в `render/Outline.ts`).

## 7. Пак животных Quaternius — Ultimate Animated Animal Pack

Источник: https://quaternius.com/packs/ultimateanimatedanimals.html
(июль 2021). Скачивание — общая папка Google Drive, id
`1uJ3N5HfB7jKTseJUNQr3N4YaN0UuEtHk`; подпапка glTF — `1yJXdB1iSrI8Db7hG77zxZ66vKsqIt0ry`.
Прямая ссылка на один файл: `https://drive.google.com/uc?export=download&id=<FILE_ID>`.
Идентификаторы нужных файлов: Cow `1lS3t1Sof0FVne1C1WXfdX48qaHES_pDG`,
Bull `1M9gyr2UikIDW_Ynp-OfgiK-JjI7ziPd3`, License.txt `1F2uy8T2fRpdc6gZ4mnS02_C2E63WvKtn`.
В паке ещё Alpaca, Deer, Donkey, Fox, Horse, Horse_White, Husky,
ShibaInu, Stag, Wolf — на тех же клипах.

Пак лежит в корне как `Quaternius_Ultimate_Animated_Animals/` рядом с
паками KayKit и так же в `.gitignore`. В репозиторий попадает только
то, что собрал `tools/prepare-animals.mjs`.

### Почему именно этот пак

У Quaternius есть более старый **Farm Animal Pack**, и **овца есть
только там**. Проверено по бинарным узлам AnimationStack во всех семи
файлах: у овцы, свиньи, ламы и мопса **всего два клипа — `Idle` и
`Jump`**. Ни ходьбы, ни выпаса. Реклама пака («run, idle, jump and
walk») для овцы просто неверна. Полный набор из шести клипов есть
только у коровы, лошади и зебры.

Отсюда решение: **скот, а не овцы**. Корове в английской долине
оправдание не нужно, а тринадцать клипов Ultimate-пака включают
`Eating` и `Idle_Headlow` — ровно то, чем животное на поле занято
почти всё время.

### Что внутри

| | cow | bull |
|---|---|---|
| треугольников | 2450 | 2418 |
| вершин | 4970 | 4906 |
| примитивов | 7 | 7 |
| костей | 42 | 42 |
| клипов в паке | 13 | 13 |
| оставлено | 5 | 5 |
| файл после сборки | 214 КБ | 213 КБ |

Габарит в единицах пака (cow): **2.312 × 4.587 × 8.067** (X × Y × Z,
Y — высота, Z — длина). Это не метры: масштаб считается в коде из
`ANIMAL_LENGTH`, потому что животные пака смоделированы в разный
размер и одним множителем осла не отличить от лошади. В мире выходит
**0.44 × 0.88 × 1.55 м** — спина коровы по грудь полурослику ростом
1.1 м.

Кости: у cow и bull риг совпадает вершина в вершину (42), у donkey и
horse — свой, на 50 костей. Клипы между этими двумя ригами **не**
переносятся, в отличие от KayKit `Rig_Medium`. Каждое животное несёт
свои клипы в своём файле, отдельных файлов анимаций тут нет.

### Текстур нет вовсе

`images: 0`, `textures: 0`. Весь цвет — плоский `baseColorFactor` на
семи именованных материалах. Это и есть причина, по которой пак так
легко ложится на решение №6: перекраска — прямой поиск по имени
материала в `SLOTS` (`src/config/animals.ts`), и от собственной палитры
ассета не остаётся ничего.

| материал | слот | откуда цвет |
|---|---|---|
| `Main` | coat | масть, `COATS` |
| `Main_Dark` | coatDark | масть × 0.72 |
| `Main_Light` | pale | `PALETTE.hidePale` |
| `Hooves` | hoof | `PALETTE.hoof` |
| `Muzzle` | muzzle | `PALETTE.muzzle` |
| `Horns` | horn | `PALETTE.horn` |
| `Hair` | mane | `PALETTE.mane` (у осла и лошади) |
| `Eye_Black` / `Eye_Dark` | eyeDark | `PALETTE.eyeDark` |
| `Eye_White` | eyeWhite | `PALETTE.eyeWhite` |

Имя материала, которого нет в таблице, — **ошибка загрузки**, а не
молчаливый дефолт. Иначе новое животное приедет в цвете, который
палитра никогда не выбирала, а именно это правило и запрещает.

### Оставленные клипы

`Idle`, `Idle_2`, `Idle_Headlow`, `Eating`, `Walk`. Играются первые
четыре. **`Walk` лежит в файле и намеренно не проигрывается**: у клипа
нет корневого перемещения, а `Livestock` животное не двигает — идущая
корова топталась бы на месте посреди поля. Клип оставлен, потому что
дать стаду куда идти — отдельная задача, а не потому, что он забыт.

Остальные восемь (`Attack_Headbutt`, `Attack_Kick`, `Death`, `Gallop`,
`Gallop_Jump`, два `Idle_HitReact`, `Jump_toIdle`) — для игры, в
которой дерутся. Их вырезает сборка, и на них приходится почти весь
размер файла.

### Сборка: tools/prepare-animals.mjs

`prune` → `resample` → `meshopt --level high`. 3041 КБ → 214 КБ.

Предупреждение из `compress-animations.mjs` — что квантование
запекается в `inverseBindMatrices` и раскалывает один скин на
несколько, по мешу на каждый — здесь **не действует**: у животного
один меш с одним скином, раскалывать нечего. Семь его примитивов
сливаются в один уже при загрузке и все сидят на этом одном скине.

Скрипт проверяет себя, как и два соседних: сверяет имена клипов, их
длительности до миллисекунды, число каналов и набор костей до и после
и печатает `check ok`. Это не формальность — `resample` ровно тот шаг,
который способен молча укоротить клип.

**`join` примитивов на этапе сборки делать нельзя.** Он стирает имена
материалов, а на них держится вся раскраска.

### Цена в кадре

36 голов на 13 пастбищах. Один вызов отрисовки плюс обводка на голову,
скелет на 42 кости, свой микшер. Лестница LOD — та же, что у жителей
(`LOD_CULL`, `LOD_NEAR`, `LOD_ANIMATION_STRIDE`).

Замерено: 8.2–8.7 мс медиана в четырёх точках, упор в вертикальную
синхронизацию; худшее число вызовов 230 с высоты карты. Сборка
библиотеки 29 мс, расстановка стада 26 мс.

Для сравнения — то, что стадо заменило. Девяносто семь неподвижных
овец из примитивов уходили в общий `PropBatch`, и в коммите об этом
