# Каталог ассетов

Составлено разбором самих файлов, а не по именам. Временный скрипт-инспектор
парсил контейнер GLB вручную (заголовок → JSON-чанк → BIN-чанк) и считал:
треугольники по `accessor.count / 3` у индексного аксессора каждого примитива,
длительность клипа как максимум по `accessor.max[0]` входных сэмплеров
анимации (это ровно то число, которое three.js положит в `AnimationClip.duration`),
кости — по `skins[].joints` с разыменованием в имена узлов, UV — чтением
`TEXCOORD_0` из буфера, размеры PNG — из чанка IHDR. Скрипт лежал в
scratchpad и в проект не попал.

## Фактическая структура на диске

Оба пака распакованы с **лишним уровнем вложенности** — имя папки продублировано:

KayKit_Character_Animations_1.1/KayKit_Character_Animations_1.1/...

## 2. assets/characters/halfling_base.glb — сверка

Разбор подтверждает всё, что записано в CLAUDE.md:

- 6 мешей, **7478 тр.** суммарно: `Rogue_Head` 2606, `Rogue_Body` 1436,
  `Rogue_LegLeft`/`Rogue_LegRight` по 930, `Rogue_ArmLeft`/`Rogue_ArmRight` по 788
- плащ `Rogue_Cape` удалён, лишних узлов (камера, свет) нет
- скелет `Rig_Medium`, 23 кости, **рест-поза побитово совпадает с Rogue.glb**
- высота 2.1804, `2.1804 × 0.50451 = 1.1000` — константа верна
- одна встроенная текстура 1024×1024, **sha1 совпадает с `rogue_texture.png`**
  из пака: файл не перекодировался
- один материал `rogue`: `doubleSided = true`, `alphaMode = OPAQUE`,
  `metallic = 0`, `roughness = 0.5`
- экспортёр — Blender glTF I/O v5.2.39 (у файлов пака v1.7.33)

`doubleSided = true` стоит учесть на шаге стилизации: обводка методом
inverted hull делается через `side: BackSide` на копии меша, а
двусторонний материал ей мешает — оболочку надо делать отдельным
материалом с явным `BackSide`, а не клоном исходного.

## 3. Скелет Rig_Medium

23 кости. Иерархия (проверена по `nodes[].children`):

```
Rig_Medium (узел-контейнер, не кость)
└─ root
   └─ hips
      ├─ upperleg.l → lowerleg.l → foot.l → toes.l
      ├─ upperleg.r → lowerleg.r → foot.r → toes.r
      └─ spine → chest
                 ├─ head
                 ├─ upperarm.l → lowerarm.l → wrist.l → hand.l → handslot.l
                 └─ upperarm.r → lowerarm.r → wrist.r → hand.r → handslot.r
```

Полный список имён: `root`, `hips`, `spine`, `chest`, `head`,
`upperleg.l/r`, `lowerleg.l/r`, `foot.l/r`, `toes.l/r`,
`upperarm.l/r`, `lowerarm.l/r`, `wrist.l/r`, `hand.l/r`, `handslot.l/r`.

`handslot.l` / `handslot.r` — пустые кости-крепления на конце кисти,
готовые точки привязки для инструментов (лейка, удочка, корзина).

### Совпадают ли кости — да

Проверено попарно между всеми шестью персонажами Adventurers,
`halfling_base.glb` и всеми восемью файлами анимаций `Rig_Medium`:

- **имена костей** — идентичны, 23 из 23, ни одного расхождения
- **иерархия** — идентична
- **локальная рест-поза** (translation / rotation / scale каждой кости) —
  идентична с точностью до 1e-5

Порядок костей в массиве `skins[].joints` между файлами различается, но это
неважно: `THREE.AnimationMixer` связывает треки с костями **по имени узла**,
а не по индексу. Ретаргет действительно не нужен.

Каналы клипов адресуют только эти 23 кости, узлов вне скелета в анимациях нет.
Свойства — `translation`, `rotation`, `scale`.

### Два исключения, о которых надо знать

**`Mannequin_Medium.glb`** (`Mannequin Character/characters/`) — в его скине
**21 кость**, нет `handslot.l` и `handslot.r`. На сами файлы анимаций это не
влияет: там скин полный, 23 кости. Просто не использовать этот меш как эталон.

**`Rig_Large` — те же имена костей, но другой скелет.** Имена, иерархия и
количество (23) совпадают с `Rig_Medium` полностью, а рест-поза отличается
у 22 костей из 23: `hips` смещён на 0.636, `head` на 0.757, `upperarm.*` на
0.672 — модель вдвое выше (3.98 против 2.18). Это ловушка: клип из
`Rig_Large_*` **проиграется на нашем скелете без единой ошибки** и молча
изуродует персонажа. Ориентироваться только на путь файла, не на имена костей.

### Root motion

Кость `root` анимируется каналом `translation` во всех клипах, но фактическое
смещение нулевое везде, кроме четырёх уворотов:

| Клип | Смещение root |
|---|---|
| `Dodge_Forward` | 0.25 по Z |
| `Dodge_Backward` | 0.65 по Z |
| `Dodge_Left` / `Dodge_Right` | 0.50 по X |

То есть **ходьба и бег бегут на месте** — перемещение целиком на
контроллере. Это то, что нужно: скорость персонажа задаётся кодом, а
скорость проигрывания клипа подгоняется под неё через `action.timeScale`,
чтобы ноги не проскальзывали.

### Устройство атласа — регулярная сетка 8×4

Разобрал попиксельно, с сегментацией по резким переходам цвета. Все пять
атласов устроены одинаково: **8 колонок × 4 ряда = 32 ячейки по 128×256 px**.

### Сколько цветов реально сэмплит каждая часть

Просэмплировал атлас в каждой UV-вершине. Часть задевает 68–229 уникальных
значений, из них «значимых» (≥1% вершин) — 23–42. Плоских треугольников,
у которых все три вершины попали в один цвет, — от 0.7% до 25%.

То есть **градиент внутри ячейки используется по назначению**: мягкая
растушёвка запечена в текстуру. Для toon-шейдера из решения №5 это плохо —
двойное затенение, ступени лягут поверх готового градиента и картинка
замылится. См. раздел 9.

### Обрезка файлов анимаций

`tools/strip-anim-meshes.mjs` — одноразовый инструмент без зависимостей,
разбирает и пересобирает GLB вручную. Удаляет `meshes`, `skins`, `materials`
и шесть узлов манекена; оставляет узлы костей с рест-позой, `animations`
и только те аксессоры, на которые ссылаются сэмплеры клипов. Данные
аксессоров перепаковываются плотно, каждому свой `bufferView`.

| Файл | Было | Стало | По сети (brotli) |
|---|---:|---:|---|
| `general.glb` | 809 КБ | 420 КБ | 228 → 117 КБ |
| `movement.glb` | 673 КБ | 285 КБ | 180 → 70 КБ |
| `movement_advanced.glb` | 703 КБ | 314 КБ | 193 → 83 КБ |
| `simulation.glb` | 836 КБ | 448 КБ | 289 → 178 КБ |
| `tools.glb` | 1427 КБ | 1039 КБ | 452 → 342 КБ |
| **итого** | **4.34 МБ** | **2.45 МБ** (−44%) | **1.31 МБ → 790 КБ** (−41%) |

Бинарная часть ужалась до теоретического минимума: в `general.glb`
BIN-чанк ровно 203 КБ — столько и весят данные клипов. Остаток —
JSON-чанк (217 КБ на 997 аксессоров), но он сжимается почти нацело,
поэтому дальше не оптимизировал: дедупликация аксессоров и общий
`bufferView` дали бы по сети меньше 80 КБ на все пять файлов.

### Проверки после обрезки

Прошли на всех пяти файлах:

- имена клипов, длительности и число каналов совпадают с исходником
  побайтово по отпечатку
- 82 клипа суммарно, ни один не потерян
- все 23 целевые кости каждого файла есть в скине `halfling_base.glb`
- после санитизации имён по правилам `THREE.PropertyBinding` (точки
  вырезаются: `upperleg.l` → `upperlegl`) 23 имени остаются уникальными,
  коллизий привязки не будет

Перегенерировать в любой момент:

```bash
node tools/strip-anim-meshes.mjs
```

## 9. Находки, требующие решения

**Перекраска сдвигом UV работает, но `map.offset` — не тот рычаг.**
Решение №3 в CLAUDE.md по сути верное: сетка 8×4 регулярная, сдвиг на
0.125 по U или 0.25 по V переносит **все** острова части на соседнюю
ячейку когерентно. 32 позиции при `RepeatWrapping`.

Проблема в другом. `map.offset` живёт на материале, а по решению №1 шесть
частей склеиваются в один `SkinnedMesh` с одним материалом — значит одним
`offset` нельзя покрасить голову иначе, чем ноги. А интерфейс
`VillagerConfig` требует ровно этого: `palette: { head, body, legs }`.

Рабочий вариант: **запекать смещение прямо в UV во время склейки**. Склейка
и так происходит (решение №1), и на этом шаге к `TEXCOORD_0` вершин каждой
части прибавляется свой `(du, dv)` из сетки 8×4. Один материал, одна
текстура, один draw call, перекраска по частям, детерминированность от seed.
Это уточнение механики решения №3, а не отмена — **нужно подтверждение**.

Второе, отдельное: ячейки атласа — градиенты с запечённой растушёвкой
(см. раздел 6), а решение №5 требует toon с 2–3 ступенями. Поверх градиента
ступени дадут грязь. Плюс решение №6 запрещает ассетам приносить свои цвета,
а сейчас цвета именно из пака.

Лечится тем же способом и без Blender: сгенерировать **свой атлас
1024×1024 по той же сетке 8×4** из `config/palette.ts` — 32 ячейки, в каждой
2–3 плоские ступени вместо градиента. UV не трогаются вообще, развёртка
пака остаётся валидной, вес такой же (~15 КБ). Заодно снимается разнобой
пяти атласов: части разных персонажей поедут на одну текстуру, а сейчас
у Mage и Knight на одной позиции сетки разные цвета.

Ни то, ни другое не блокирует шаги 1–2 из PROMPTS.md: там материалы серые.
Решать имеет смысл на шаге 3.

**Столкновение имени `T-Pose`** — есть во всех восьми файлах анимаций.
При сборке общего реестра клипов нужен префикс по файлу либо явный отсев.

**`doubleSided = true`** у всех материалов персонажей — помешает обводке
inverted hull, см. раздел 2.
